Runbook
值班只看四件事：症狀、第一步、升級條件、結案條件。
01

GPU / Server

症狀：GPU 掉卡、Xid、PCIe、Host 異常

先做：確認影響節點 → 收集 Log → Isolate

升級：多卡 / 多節點 / 重複故障

02

Network

症狀：Switch、Link、BMC、OOB 異常

先做：確認範圍 → Port / Link / Route 檢查

升級：多節點或服務中斷

03

Facility

症狀：Power、Cooling、CDU、溫度異常

先做：確認告警 → 降低服務風險

升級：影響機櫃 / 多設備 / 持續惡化

04

Operations

症狀：Restart、Change、維運操作

先做：確認授權 → 執行 → 驗證

升級：生產服務或大範圍影響

標準處置流程

01確認影響服務、節點、範圍
→
02執行處置依對應 Runbook
→
03確認恢復服務 + 監控正常
→
04更新工單原因、處置、下一步

相同問題再次發生轉 Problem / RCA
還在等 Vendor / RMA保持 Blocked + ETA
監控仍有異常繼續觀察，不結案

ITIL
ITIL 4 的 7 大指導原則，用日常維運語言快速理解。
01

聚焦價值

先確認對服務與使用者的影響。

維運：優先處理高影響事件與 SLA 風險。
02

從現況開始

先使用現有資料，不急著全部重做。

維運：先看監控、Log、Jira、CMDB 與 Runbook。
03

迭代前進並取得回饋

小步處理，每一步都驗證。

維運：修復 → 驗證 → 觀察 → 改善。
04

協作並提高可視性

讓相關團隊看到相同狀態與責任。

維運：Incident、Owner、進度與下一步要清楚。
05

整體思考與工作

不要只修單一設備，要看完整服務。

維運：同時確認 GPU、Network、Facility 與服務影響。
06

保持簡單實用

只保留真正有助於決策的流程與資訊。

維運：能 3 步完成，就不要設計成 10 步。
07

最佳化並自動化

先把流程做好，再自動化重複工作。

維運：告警聚合、自動蒐證、健康檢查與週報。
